# Access 插件配置文件

自 v3.1.2 起，Access 的插件配置可以放在这个目录下的 `current.yaml` 里，随代码一起部署。

- **启用插件**时，若存在 `current.yaml`，就按它设置插件；
- **禁用插件**时，把当时的配置写回同一个文件。

于是「禁用导出 → 换机器 / 重建容器 → 放回文件 → 启用导入」是闭合的，不必再到后台一项项填。

文件里**写了的项按文件走，没写的项使用默认值**——加载一次相当于把插件配置整体替换成文件描述的样子。

## 快速开始

把下面的示例保存为本目录下的 `current.yaml`，按需修改，然后在后台启用插件即可。
只保留需要改的项也可以，其余会走默认值。

```yaml
# Access 插件配置示例
#
# 布尔项写 1 / 0 或 true / false 都可以。
# 值里如果有 # 或需要保留字面量（例如字符串 "off"），用双引号括起来。

access:
  # ── 基本 ────────────────────────────────────────────────
  pageSize: 20                    # 每页日志条数
  isDrop: 0                       # 禁用插件时是否删除数据表：0 否，1 是
  writeType: 1                    # 日志写入方式：0 前端，1 后端

  # ── IPinfo 归属地查询 ───────────────────────────────────
  isPaid: 0                       # 0 Lite（免费），1 Core（付费）
  isToken: ""                     # IPinfo 接口令牌
  socks5Host: ""                  # SOCKS5 代理，格式 主机:端口，留空不使用
  socks5Auth: ""                  # SOCKS5 认证，格式 用户名:密码

  # ── Redis 缓存与写入队列 ────────────────────────────────
  redisCache: 0                   # 0 禁用，1 启用
  redisHost: "127.0.0.1"
  redisPort: 6379
  redisAuth: ""                   # 留空表示无密码
  writeQueue: 1                   # 1 自动（配了 Redis 才生效），0 禁用
  queueFlushSize: 500             # 队列积压到这个条数就入库一次
  queueFlushInterval: 60          # 距上次入库超过这么多秒也入库一次

  # ── 统计数据库 ──────────────────────────────────────────
  # dbType 为 follow 时与 Typecho 共用一个库，下面的项都不生效
  dbType: "follow"                # follow / mysql / pgsql
  dbHost: "127.0.0.1"
  dbPort: ""                      # 留空按类型取默认端口（MySQL 3306，PostgreSQL 5432）
  dbUser: ""
  dbPass: ""
  dbName: ""                      # 选独立数据库时必填，需预先建好
  dbPrefix: "typecho_"            # 最终表名为 [前缀]access
  dbCharset: ""                   # 留空按类型取默认字符集（MySQL utf8mb4，PostgreSQL utf8）
```

## 全部配置项

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `pageSize` | `20` | 每页显示的日志条数 |
| `isDrop` | `0` | 禁用插件时是否一并删除数据表，`1` 为删除且不可恢复 |
| `writeType` | `1` | `0` 前端写入，`1` 后端写入 |
| `isPaid` | `0` | IPinfo 接口类型，`0` Lite，`1` Core |
| `isToken` | 空 | IPinfo 接口令牌 |
| `socks5Host` | 空 | SOCKS5 代理地址，格式 `主机:端口` |
| `socks5Auth` | 空 | SOCKS5 代理认证，格式 `用户名:密码` |
| `redisCache` | `0` | 缓存加速，`1` 启用 |
| `redisHost` | `127.0.0.1` | Redis 地址 |
| `redisPort` | `6379` | Redis 端口 |
| `redisAuth` | 空 | Redis 密码 |
| `writeQueue` | `1` | 写入队列，`1` 自动（需先配 Redis），`0` 禁用 |
| `queueFlushSize` | `500` | 队列积压达到该条数触发入库 |
| `queueFlushInterval` | `60` | 距上次入库超过该秒数触发入库 |
| `dbType` | `follow` | 统计数据库类型：`follow` 跟随 Typecho、`mysql`、`pgsql` |
| `dbHost` | `127.0.0.1` | 独立数据库地址，MySQL 也可填 unix socket 路径 |
| `dbPort` | 空 | 留空按类型取默认端口 |
| `dbUser` | 空 | 独立数据库用户名 |
| `dbPass` | 空 | 独立数据库密码 |
| `dbName` | 空 | 独立数据库库名，选独立数据库时必填 |
| `dbPrefix` | `typecho_` | 独立数据库中的表前缀，最终表名为 `[前缀]access` |
| `dbCharset` | 空 | 留空按类型取默认字符集 |

## 格式说明

只实现了够用的 YAML 子集，不依赖任何扩展；装了 PHP 的 `yaml` 扩展时会优先用它解析，
对本文件这种写法两者结果一致。

支持：

- 顶层 `access:` 段，段内每行一个 `键: 值`（也接受不带顶层段的平铺写法）；
- 裸标量、单引号、双引号字符串，双引号内支持 `\"` `\\` `\n` `\t`；
- `#` 起的行内注释、空行、文档分隔符 `---` / `...`；
- `true` / `yes` / `on` 归一为 `1`，`false` / `no` / `off` 归一为 `0`，`null` / `~` 归一为空串。

不支持列表、多行标量、锚点等，本插件的配置也用不到。

两个容易踩的点：

- **带引号的值一律按字面量处理**，`dbName: "off"` 是字符串 `off` 而不是布尔假；
- **不认识的键会被忽略**，写错键名不会报错，只是不生效——改完建议在启用提示里确认一句
  「已从 config/current.yaml 加载插件配置」。

## 出错时的行为

| 情况 | 行为 |
| --- | --- |
| 文件不存在 | 什么都不做，沿用数据库里已有的配置 |
| 解析失败、文件不可读 | **不阻断启用**，在启用成功的提示里说明原因，沿用已有配置 |
| 文件指定的独立数据库连不上 | 启用照常失败并报错，且**不会**覆盖数据库中已有的配置 |
| 文件里配置的 Redis 连不上 | **不阻断启用**，缓存与写入队列自动降级，提示里说明；同时记入熔断，避免前台请求逐个去撞连接超时 |
| 禁用时目录不可写 | **不影响禁用**，只在提示里说明配置没能写出 |

建表是在应用文件配置**之后**进行的，所以文件里指定的独立数据库会立刻生效，
不需要先启用再去后台改一遍。

## 安全

`current.yaml` 含有数据库密码、Redis 密码和 IPinfo 令牌。

- 插件写出该文件时权限设为 `0600`；
- 本目录附带 `.htaccess` 与空 `index.html` 阻止 Web 直接下载；
- **Nginx 下 `.htaccess` 不起作用**，需要自行在站点配置里拒绝该目录，例如：

  ```nginx
  location ^~ /usr/plugins/Access/config/ {
      deny all;
  }
  ```

- 插件的 `.gitignore` 已包含 `config/current.yaml`，默认不会被提交；
  如果确实需要把配置纳入版本管理，建议先把密码类字段清空，改由环境注入。
